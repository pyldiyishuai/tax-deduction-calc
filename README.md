# 个税专项附加扣除计算器

> 年收入 24 万、一个孩子、租房、赡养老人：
> 填了之后一年少缴 **7,320 元**。不填，这钱就白交了。

纯静态站点，双击 `index.html` 就能跑。

---

## 一、先说最重要的一件事

**专项附加扣除不会自动生效。**

税务系统不知道你有没有孩子、有没有租房、有没有赡养老人。
必须自己在「个人所得税」App 里填报，然后选择由单位按月扣除，
或者次年汇算清缴时扣除。

**不填 = 放弃 = 白交税。**

好消息：当年忘填，次年 3 月 1 日至 6 月 30 日汇算清缴时补填，
多缴的税会退回来。

## 二、七项扣除标准（2023 年 8 月起）

| 项目 | 标准 | 说明 |
|---|---|---|
| 3 岁以下婴幼儿照护 | 2,000 元/月/每个 | 从出生当月到满 3 周岁前一月 |
| 子女教育 | 2,000 元/月/每个 | 从满 3 岁到全日制学历教育结束 |
| 继续教育 | 学历 400 元/月；职业资格 3,600 元/年 | 学历最长 48 个月 |
| 大病医疗 | 超 15,000 元部分，年限额 80,000 | 只算医保目录内自付 |
| 住房贷款利息 | 1,000 元/月 | 首套，最长 240 个月 |
| 住房租金 | 1,500 / 1,100 / 800 元/月 | 按城市规模分档 |
| 赡养老人 | 独生 3,000 元/月；非独生分摊 ≤1,500 | 按纳税人算，不按老人数 |

**2023 年提高了三项**：婴幼儿照护 1,000→2,000、子女教育 1,000→2,000、
赡养老人 2,000→3,000。

## 三、算例（工具默认值）

年收入 240,000，社保公积金个人缴 36,000，
1 个子女在读、租房（1,100 档）、独生子女赡养老人。

### 计算过程

```
应纳税所得额（不填扣除）
  = 240,000 − 60,000（基本减除）− 36,000（社保）= 144,000
应缴个税 = 144,000 × 10% − 2,520 = 11,880

专项附加扣除合计
  = 子女教育 24,000 + 住房租金 13,200 + 赡养老人 36,000 = 73,200

应纳税所得额（填了扣除）
  = 144,000 − 73,200 = 70,800
应缴个税 = 70,800 × 10% − 2,520 = 4,560

一年少缴 = 11,880 − 4,560 = 7,320 元（每月 610 元）
```

### 分档明细

| 档位 | 金额 | 税额 |
|---|---|---|
| 3% | 36,000 | 1,080 |
| 10% | 34,800 | 3,480 |
| **合计** | **70,800** | **4,560** |

## 四、关键概念：不是「抵税」，是「减少应纳税所得额」

这是最容易误解的地方。

扣除 2,000 元，如果你的税率是 10%，实际少缴 **200 元**，不是 2,000 元。

```
节税金额 = 扣除金额 × 你的边际税率
```

| 边际税率 | 每扣 1,000 元少缴 |
|---|---|
| 3% | 30 元 |
| 10% | 100 元 |
| 20% | 200 元 |
| 25% | 250 元 |
| 30% | 300 元 |
| 35% | 350 元 |
| 45% | 450 元 |

**推论 1**：收入越高，同样的扣除越值钱。
**推论 2**：夫妻之间，让税率高的一方扣更划算。

---

## 五、夫妻分配算例

一个孩子，每月 2,000 元额度。一方税率 20%，另一方 10%。

| 分法 | 一年节税 |
|---|---|
| 各扣 50% | 1,000×12×20% + 1,000×12×10% = **3,600** |
| 20% 一方全扣 | 2,000×12×20% = **4,800** |
| 差 | **1,200 元** |

分法一旦确定，一个纳税年度内不能变更。

## 八、改代码前必看

### 1. 边际税率要用「扣除后」的应纳税所得额算

```js
var rate = marginalRate(taxableFull || taxableBase);
```

如果用扣除前的算，高收入用户会被高估抵税价值。
比如 24 万收入，扣除前是 10% 档（144,000），
扣除后还是 10% 档（70,800）——这个例子相同，
但 60 万收入的情况：扣除前 30% 档，扣除后可能降到 25% 档。

### 2. 大病医疗是「超门槛 + 封顶」双重限制

```js
var over = Math.max(paid - 15000, 0);
yearly = Math.min(over, 80000);
```

两个都漏一个就错。`paid = 15000` 时结果是 0，不是 15000。

### 3. `buildDeductions` 的 `activeCount` 别忘返回

`buildTips` 里用了 `ded.activeCount`，但 `buildDeductions` 一开始只返回
`{list, yearly, monthly}`，导致提示里出现「填了 **undefined** 项扣除」。

### 4. 社保不能超过收入

```js
var social = Math.min(Math.max(n(f.social), 0), income);
```

不钳制的话，应纳税所得额会变成负数，虽然最终 `Math.max(..., 0)` 兜住了，
但 `taxable.base` 会显示负值。

### 5. 子女/婴幼儿数量要钳制到 0–5

步进器只管 UI，用户可以在输入框里手打数字（`type="number"`）。
core 层必须再钳一次。

### 6. Hero 的示例数字必须和默认值算出来的一致

Hero 最初写「一年少缴 5,160 元」，实际默认值算出来是 7,320。
这种不一致会让用户第一眼就怀疑工具的可信度。
**改默认值或改算法后，一定要回头核对 Hero 文案。**

## 十一、免责

本工具依据《个人所得税专项附加扣除暂行办法》（国发〔2018〕41 号）
与国务院 2023 年提高三项扣除标准的通知计算。

未考虑年终奖单独计税、劳务报酬、稿酬、特许权使用费等其他所得，
也未考虑减免税优惠、捐赠扣除等特殊情形。

结果仅供参考，实际以税务机关认定为准。
